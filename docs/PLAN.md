## Idea
**Track: Information Access.** An AI-powered site that makes existing open-source "intro to programming" repos easier to approach and available in many languages. We claim none of the content as ours. Everything is open data, linked to its source repo with its license and attribution.

**What we add (our only contribution):**
1. **Translation** of open-licensed lessons into multiple languages (code and technical terms preserved, short glossary for terms).
2. **A level-based path** (Beginner / Intermediate / Advanced) that sequences existing repo material so newcomers know where to start.
3. **Clear sourcing**: every lesson links to the original repo, author, and license.

**Who it's for (details in `docs/PITCH.md`):** (1) a student who needs tutoring and finds GitHub repos unapproachable, and (2) international students who struggle with English-only resources.

**Why it matters:** repos are free but hard to approach and mostly English-only. We lower both barriers.

## Two sides
- **Learn** — sourced from [sindresorhus/awesome](https://github.com/sindresorhus/awesome) (CC0): curated "awesome" lists for learning topics.
- **Build** — sourced from [codecrafters-io/build-your-own-x](https://github.com/codecrafters-io/build-your-own-x) (CC0): "build your own X" tutorials (databases, git, shell, etc.).
- Both are link lists. We translate + level-tag the list entries and link out. Details in `docs/SOURCES.md`.

## Audience update: children just starting to learn
Most kids' coding tutoring is pay-to-use. We now focus on **young beginners (about ages 5-13) and the parents/teachers who help them**, plus non-English speakers.
- **Flagship feature: "What should I learn?" guide** (`/<lang>/guide`, `src/guide.py`). Multiple-choice only (age, goal, level), and the AI picks an ordered 6-step path from our data. It may only choose existing entry ids, so it can't invent links. Falls back to keyword matching with no API key.
- **Child safety:** no accounts, no free-text input, no personal data stored, no ads/tracking. Keep language simple and friendly. Mention that adults should supervise.
- **OPEN RISK (Data lead):** `awesome` and `build-your-own-x` are written for adult developers and are NOT kid-focused. We must add child-friendly **open-licensed** sources and record each in `docs/SOURCES.md` after checking the license. Found so far: `uccser/cs-unplugged` (MIT code; check its content license before reuse). Keep the existing two as the "older learners" tier.
- `scripts/translate.py` now also tags `age_group` (5-7, 8-10, 11-13, teen+).

## Principles
- Open data only. Only use content under licenses that allow translation/redistribution (CC-BY, MIT, etc.). Record license per source.
- Never present content as ours. Show attribution + "translated from" on every page. Note translations are AI-generated.
- Keep code blocks untouched; translate prose only.

## Tech Stack (Python)
| Layer | Choice | Why |
|-------|--------|-----|
| Language | Python 3.9+ | Whole team can contribute; one language for site and pipeline |
| Web | Flask + Jinja2 (server-rendered) | Simple, fast to build; routes `/<lang>/learn`, `/<lang>/build` |
| Styling | Tailwind via CDN | No build step; `dir="rtl"` for Arabic |
| Translation + level tagging | `anthropic` SDK (`claude-haiku-5-5` bulk, `claude-sonnet-5-5` spot checks) | Good technical translation; one call can also assign a level |
| Data | Static JSON in `src/data/`, generated by `scripts/` | No database, fast, free to host |
| Hosting | Render (or Railway/Fly) | Free tier, deploys from GitHub |

**Pipeline:** `scripts/fetch.py` downloads each source README and parses list entries -> `scripts/translate.py` has Claude translate titles/descriptions (keeping code/technical terms) and assign Beginner/Intermediate/Advanced -> JSON in `src/data/` -> Flask renders it. Translate **ahead of time**, not live, so the demo is fast and the API key never reaches the browser.

**Data contract** (`src/data/learn.json`, `src/data/build.json`, each a list of entries):
`{id, category, tag, title:{en,...}, desc:{en,...}, level, age_group, topic, safety, safety_reasons, url, source, license}`
- `id`: `<learn|build>-<8 hex of sha1(url)>`, stable between runs. `tag`: language tag from build-your-own-x (e.g. "Python"), else "".
- `level`: Beginner | Intermediate | Advanced
- `age_group`: youngest suitable age: "5-7" | "8-10" | "11-13" | "teen+"
- `topic`: games | art | web | general | systems | security | other
- `safety`: "kid-safe" | "ask-a-grown-up" | "adult-only"
- `safety_reasons`: short strings, empty only for kid-safe (e.g. "security-tooling", "external-forum", "account-required", "unvetted-external-site", "unclassified")
- Entries are sorted kid-safe first, then Beginner first (translate.py works in file order).

**Pipeline order:** `fetch.py` -> `categorize.py` -> `translate.py` (then `coverage.py`, `check_links.py`, `python -m unittest discover -s tests`).

**Git:** branch per person (`data`, `ai`, `backend`, `frontend`), small commits, pull before push, merge to `main` often.

## Decisions
- **Categorize, don't filter.** We keep every entry from the two existing CC0 sources and tag each one, so the site serves young learners (5-13) and still offers advanced material. No new sources up front; add one only if coverage results show gaps (`python scripts/coverage.py`). Candidate if needed: `uccser/cs-unplugged` (verify its code AND content licenses first, add a `docs/SOURCES.md` row before using it).
- **Safety tiers:** `kid-safe` (nothing risky in the listing), `ask-a-grown-up` (forums/social platforms, accounts or payment, security or network topics, crypto/finance, unvetted sites, or just unclear), `adult-only` (hacking/exploit/malware tooling, adult content).
- **YouTube/Vimeo links are treated as normal (not flagged).** We rely on YouTube's own age restrictions rather than gating every video.
- **Fail closed:** unclear means `ask-a-grown-up`, never `kid-safe`. `kid-safe` also requires a kid topic (games/art/web/general) and a vetted link host. The AI pass can only make an entry stricter, never looser than the rules. We classify titles, descriptions, categories and link hosts only, never the linked pages.
- **Parental gate (design):** by default the site hides `ask-a-grown-up` and `adult-only` entries. An adult can reveal `ask-a-grown-up` entries for the current session only (a simple "I'm a grown-up" confirmation; `adult-only` stays hidden). No accounts, no personal data stored.
- Rules alone leave most entries with unknown topic or level (they default to Intermediate/"unclassified"). The Claude pass (`python scripts/categorize.py`, needs `ANTHROPIC_API_KEY` in a local `.env`) fills those in; results are cached in `scripts/cache/categorize.json`.
