# Browser-only progress (spec)

> **Status (Nov 8): done.** Progress is implemented in `public/static/galaxy.js` (see "Update (Nov 8)" near the end). The sections below are the original design, kept for the reasoning; the hooks were wired in and the separate `progress.js` was removed.

A child can mark entries and lessons as done, and see a count and stars, with **no account and nothing sent to the server**. Progress lives in the child's own browser (`localStorage`). This keeps our promise: no accounts, no personal data.

Files (all new; no existing page was restyled and no existing template or `app.py` was edited):
- `public/static/progress.js`: vanilla JavaScript, one small module. No libraries, no network calls, no cookies, no `innerHTML`.
- `public/static/progress.css`: styles only for the controls the script adds (logical CSS properties, so RTL works).
- `src/data/progress_text.json`: UI strings in en, es, ar, hi, pt. **AI-generated by Claude Code; not yet checked by native speakers.** The `_note` key is for humans only, so don't pass it to the page.
- `tests/progress.test.js` (Node, no packages) and `tests/test_progress_static.py`.

## Storage
One key, `hc_progress_v1`, value `{"v":1,"done":{"<item id>":1}}`.
- Ids only: entry ids (`kids-xxxxxxxx`, `learn-xxxxxxxx`, `build-xxxxxxxx`) and lesson ids (`lesson-xxxxxxxx`). Each must match `/^[a-z]+-[0-9a-f]{8}$/`.
- No names, no timestamps, no free text. At most 2000 ids.
- Every read and write is in `try/catch`. If storage is unavailable (private mode, blocked), pages work normally, progress lasts until the page is closed, and a quiet note says "Progress can't be saved in this browser."
- Corrupt or foreign data in the key is ignored (treated as empty). Invalid ids are dropped. Nothing read from storage is ever used as a URL or as HTML; all text is set with `textContent`.

## Progressive enhancement and data attributes
Pages are complete with JavaScript off. The script looks for these attributes and adds the controls itself:

| Attribute | Put it on | What the script adds |
|---|---|---|
| `data-progress-item="<id>"` | the main `<article>` of an entry or lesson page | a "Mark as done" toggle button (`aria-pressed`, keyboard accessible, visible focus) that becomes "Done" with a check |
| `data-progress-list` | a list container | a check mark on each descendant `[data-progress-id="<id>"]` that is done |
| `data-progress-summary` | an element inside (or next to) the list | "3 of 26 done" |
| `data-progress-roadmap="id,id,id"` | a guide or group | "2 of 5 steps done" |
| `data-progress-stars` | any inline element (lessons list, home page) | five stars: one filled star for every 3 completed items, up to 5. Filled `★` vs outline `☆` (not colour alone) and `role="img"` with an `aria-label` such as "2 of 5 stars" |
| `data-progress-panel` | an empty `<section>` on the lessons list | the "My progress" panel: count, stars, **Start again** (inline two-step: it turns into "Yes, clear my progress" and "Cancel", no `window.confirm`), **Copy my progress code**, **Use a progress code** |
| `data-progress-privacy` | an empty `<p>` in the footer | the privacy sentence (fill it server-side too, so it shows without JavaScript) |

### Progress code (move progress to another device)
The code is base64 of the JSON above (ASCII only). On import it is validated strictly: only characters of base64, at most 60,000 characters, JSON with `v: 1` and a `done` object, ids must match the pattern (others are ignored), and **more than 2000 ids rejects the whole code**. The code is never evaluated. Importing merges with existing progress (union, capped at 2000).

## Text and languages
All visible text comes from `window.HC_PROGRESS_TEXT`. The page fills it from a non-executable JSON block (allowed by any CSP): `<script type="application/json" id="hc-progress-text">{{ progress_text | tojson }}</script>`. English is built into `progress.js` as the fallback for any missing string. Privacy sentence (all five languages are in `progress_text.json`): "Your progress is saved only in this browser. Nothing is sent to us."

## Accessibility
- One polite `aria-live` region (`#hc-progress-live`) announces "Marked as done", "Progress cleared", "Progress added", etc.
- Buttons and inputs are at least 44px tall; focus ring is a 3px blue outline; colours meet AA (dark text on white; white on dark green `#166534`; dark amber stars `#b45309`).
- RTL: only logical properties (`margin-inline-*`, `min-block-size`, ...); checks and stars follow the page `dir`. Verified in headless Chrome with an Arabic page.
- Motion: only a short colour transition, and only inside `@media (prefers-reduced-motion: no-preference)`.

## Content-Security-Policy
The site now sends a strict Content-Security-Policy (`src/csp.py`, mirrored in `vercel.json`): own scripts only, no inline scripts, which this script was designed for (an external file, no `eval`, no network).

## Hooks (done; kept for reference)
These hooks were added to the templates when the pages were merged.

1. **`app.py`**: load the strings and pass them to every template:
   ```python
   PROGRESS_TEXT = json.loads((Path(__file__).parent / "data" / "progress_text.json").read_text(encoding="utf-8"))
   # in ctx(lang):
   "progress_text": {**PROGRESS_TEXT["en"], **PROGRESS_TEXT.get(lang, {})},
   ```
2. **`base.html`**:
   - in `<head>`: `<link rel="stylesheet" href="{{ url_for('static', filename='progress.css') }}">`
   - before `</body>`: `<script type="application/json" id="hc-progress-text">{{ progress_text | tojson }}</script>` and `<script src="{{ url_for('static', filename='progress.js') }}" defer></script>`
   - in the footer: `<p data-progress-privacy>{{ progress_text.privacy }}</p>`
3. **`entry.html`**: `<article data-progress-item="{{ e.id }}">`.
4. **Lesson page** (`/<lang>/lesson/<id>`): `<article data-progress-item="{{ lesson.id }}">`.
5. **Lessons list** (`/<lang>/lessons`):
   ```html
   <section data-progress-panel></section>
   <p data-progress-summary></p>
   <ul data-progress-list>
     {% for l in lessons %}<li data-progress-id="{{ l.id }}"> ... </li>{% endfor %}
   </ul>
   ```
6. **Home page**: `<span data-progress-stars></span>` near the heading.
7. **Entry lists** (optional): `<ul data-progress-list>` with `<li data-progress-id="{{ e.id }}">`.
8. **Guide/roadmap** (optional): `<div data-progress-roadmap="{{ ids|join(',') }}">` with the entry/lesson ids of the steps.

The guide page says "We don't store your answers." That is still true: progress never leaves the browser, and the guide's answers are not stored either.

## Options we rejected
- **Accounts with a database (for example Supabase).** Needs sign-up, personal data (names, emails) about children, consent flows, a server we must secure, and keys to manage. It breaks our "no accounts, no personal data" promise, and it is too much for a hackathon.
- **Cookies or server sessions for progress.** Cookies are sent to the server on every request and need a notice; `localStorage` stays in the browser.
- **Third-party widgets or analytics.** Not allowed (no external scripts, no tracking).
- **Optional parent accounts with child profiles** may come later (see `docs/PLAN.md` "Next steps"). Until then the progress code lets a grown-up move progress between devices.

## Tests
- `python -m unittest discover -s tests` runs `tests/test_progress_static.py` (no `innerHTML`, `eval(`, `fetch(`, `XMLHttpRequest`, cookies or URLs in `progress.js`; the key is exactly `hc_progress_v1`; every language has every string; the CSS uses logical properties). It also runs `node tests/progress.test.js` when `node` is installed and **skips with a clear message** when it isn't.
- `node tests/progress.test.js` covers add/remove, corrupt JSON, unavailable storage, import validation and size limits, counts and stars.

## Update (Nov 8): one progress system
Decision in issue #26: keep Isabella's star system (`public/static/galaxy.js`, key `openlearn-explored-v1`). `progress.js`, `progress.css` and their tests were removed. These parts of this spec were kept and moved into `galaxy.js`:
- **Privacy line** in the footer (server-rendered from `progress_text.json`).
- **"Can't be saved" note** when storage is blocked (on "My space log").
- **Progress code** to move progress to another device (copy and paste on "My space log"). Pasted codes are checked: base64 only, at most 60,000 characters, at most 2000 items, ids must match `^[a-z]+-[a-z0-9-]{1,40}$`, links must be same-site paths. Text is set with `textContent` only.
- **Two-step "Start again"** (no `window.confirm`).
- **Counts**: "3 of 26 done" on the lessons list and "2 of 5 steps done" on the guide path.
- **Coding problems** count: `problem.js` calls `window.HackProgress.markSolved(id)`.
- **Old data is moved**: anything saved under `hc_progress_v1` becomes a star once, then the old key is removed.
Not kept: the "Mark as done" button (the star button does the same job) and the five-star bar on the home page ("My space log" has medals instead).
